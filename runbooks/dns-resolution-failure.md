# Runbook: Resolving DNS Resolution Failures on a Headless Debian Server

## 📝 Issue Description
After configuring a static IP address on a headless Debian server, network connectivity was disrupted. The server could successfully ping external IP addresses (e.g., `ping 8.8.8.8`), but domain name resolution failed, returning the error: `Temporary failure in name resolution` when attempting to ping `google.com`.

## 🔍 Troubleshooting Steps
1. **Verified Layer 3 Connectivity:** Confirmed internet access was active by pinging the public Cloudflare DNS IP (`ping 8.8.8.8`).
2. **Inspected DNS Configuration:** Checked the `/etc/resolv.conf` file using `cat /etc/resolv.conf`.
3. **Identified the Root Cause:** The file contained a header indicating it was generated by `dhcpcd` but lacked valid `nameserver` entries. It appeared the DHCP client was conflicting with the newly configured static IP settings and overwriting the DNS configuration.

## 🛠️ Resolution
To permanently resolve the conflict and ensure DNS settings persist across reboots:
1. Installed the `resolvconf` package to properly manage the `/etc/resolv.conf` file (`sudo apt install resolvconf`).
2. Disabled the conflicting `dhcpcd` service (`sudo systemctl disable --now dhcpcd`).
3. Verified that the `dns-nameservers 1.1.1.1 8.8.8.8` directive in the `/etc/network/interfaces` file was correctly applied.
4. Restarted the networking service (`sudo systemctl restart networking`) and verified resolution was working using `ping google.com`.

## 💡 Lessons Learned
- Gained a deeper understanding of how Linux handles DNS resolution and the `/etc/resolv.conf` file.
- Learned how conflicting network management daemons (like `dhcpcd`) can overwrite manual configurations when switching from DHCP to a static IP.
- Practiced using tools like `ping` and `cat` to isolate network vs. DNS issues.
